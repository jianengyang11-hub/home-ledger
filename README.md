# บ้านเรา · Home Ledger

บัญชีรายรับรายจ่ายของบ้าน — ภาพรวมรายเดือน, สรุปรายปี, รายการทั้งหมด, บันทึกข้อมูล
และมุมมองมือถือ รองรับภาษาไทย / ลาว ข้อมูลเก็บบน **Supabase** สองคนเห็นข้อมูลชุดเดียวกัน

## ความปลอดภัย

ล็อกอินด้วย **Supabase Auth** (อีเมล + รหัสผ่าน) รหัสผ่านตรวจที่เซิร์ฟเวอร์ ไม่มีเก็บในหน้าเว็บ
สิทธิ์บังคับด้วย **Row Level Security** ที่ฐานข้อมูล ไม่ใช่การซ่อนปุ่ม

| การกระทำ | ใครทำได้ | บังคับที่ |
| --- | --- | --- |
| อ่านรายการ | ต้องล็อกอินแล้วเท่านั้น | RLS `to authenticated` |
| เพิ่มรายการ | ในชื่อบัญชีตัวเองเท่านั้น | RLS `who = my_name()` |
| **แก้รายการ** | **ของตัวเองได้** · บัญชีหลักแก้ของทุกคนได้ | RLS `who = my_name() or is_admin()` |
| **ยกเลิกรายการ** | **บัญชีหลักเท่านั้น** | trigger `txns_guard_void` |
| **ลบถาวร** | **ไม่มีใครทำได้ผ่านเว็บ** | ไม่มี policy `delete` |
| เปลี่ยนสิทธิ์ / รหัสผ่าน | ทำได้ใน Supabase dashboard เท่านั้น | ไม่มี policy ให้เขียน `profiles` |

**คนที่ไม่ล็อกอินอ่านอะไรไม่ได้เลย** แม้จะรู้ publishable key จากโค้ดหน้าเว็บ
และถึงต้นจะเรียก API ตรงเพื่อลบรายการ ฐานข้อมูลก็ปฏิเสธ เพราะ `is_admin()` เป็น false
เช่นเดียวกับการแก้รายการของคนอื่น หรือเปลี่ยน `who` ไปเป็นชื่อคนอื่น — `with check` กันไว้แล้ว

## ประวัติการแก้ไข

ทุกครั้งที่มีการแก้รายการ ฐานข้อมูลจะบันทึกลงตาราง `txn_edits` เองด้วย **trigger**
ว่าใครแก้ เมื่อไหร่ ฟิลด์ไหน จากค่าอะไรเป็นอะไร

หน้าเว็บจะขึ้นป้าย **"แก้ไขแล้ว N×"** ที่ท้ายแถว กดแล้วแผงประวัติจะเปิดขึ้นมา:

```
ประวัติการแก้ไข · ซื้อของเข้าบ้าน โลตัส              [ปิด]
2 ก.ย. 2569 21:32   แก้โดย ปิ่น
   จำนวนเงิน   1,280 → 1,500
   หมวดหมู่     อาหาร → ของใช้ในบ้าน
1 ก.ย. 2569 16:10   แก้โดย ปิ่น
   รายการ      (ว่าง) → ซื้อของเข้าบ้าน โลตัส
   วันที่       31 ส.ค. 2569 → 01 ก.ย. 2569
```

trigger เป็นคนเขียน ไม่ใช่หน้าเว็บ และตาราง `txn_edits` **ไม่มี policy ให้ insert/update/delete เลย**
แปลว่าปลอมประวัติไม่ได้ และลบร่องรอยการแก้ของตัวเองไม่ได้ แม้จะเรียก API ตรง

| บัญชี | อีเมล | สิทธิ์ |
| --- | --- | --- |
| ปิ่น | `jianengyang11@gmail.com` | **admin** — แก้/ลบได้ |
| ต้น | `jia@gmail.com` | member — เพิ่มได้อย่างเดียว |
| บ้านเรา | `yang11@gmail.com` | member — เพิ่มได้อย่างเดียว |

เปลี่ยนอีเมลได้ที่ `config.js` และบล็อกที่ 5 ของ `schema.sql` **ต้องแก้ให้ตรงกันทั้งสองที่**
แล้วรัน `schema.sql` ใหม่

## ตั้งค่าครั้งแรก

1. **Authentication → Users → Add user → Create new user** สร้างครบ 3 คนตามอีเมลข้างบน
   ตั้งรหัสผ่านเอง และ**ติ๊ก Auto Confirm User** ทุกคน
2. **Authentication → Sign In / Providers** → ปิด **Allow new users to sign up**
   (กันคนนอกสมัครเข้ามาเอง)
3. **SQL Editor** → วางไฟล์ `schema.sql` ทั้งไฟล์ → Run
   ท้ายสุดจะแสดง 3 แถว ตรวจว่า `ปิ่น` เป็น `admin`

### ถ้าไม่เห็นป้าย "แก้ไขแล้ว" หรือขึ้น HTTP 404

แปลว่าตาราง `txn_edits` ยังไม่มีในฐานข้อมูล (ยังไม่ได้รัน `schema.sql` บล็อก 4b)
404 ตัวนี้มาจาก Supabase ไม่ใช่ GitHub Pages — เช็คได้จาก:

```powershell
curl.exe "https://xhnuigcwbcycthqjgjzb.supabase.co/rest/v1/txn_edits?select=id&limit=1" -H "apikey: <publishable key>"
```

| ผลที่ได้ | แปลว่า |
| --- | --- |
| `401 permission denied` | ตารางมีแล้ว ถูกต้อง (anon อ่านไม่ได้ตามที่ตั้งใจ) |
| `404 PGRST205 Could not find the table` | **ตารางยังไม่มี** → รัน `schema.sql` ใหม่ทั้งไฟล์ |

## ตั้งค่าที่ `config.js`

แก้ที่ไฟล์เดียว ไม่ต้องเข้าไปยุ่งกับ `Home Ledger.dc.html` ที่ยาว 140 KB

| ค่า | ใช้ที่ไหน | ถ้าไม่ใส่ |
| --- | --- | --- |
| `SUPABASE_URL` / `SUPABASE_ANON_KEY` | เชื่อมฐานข้อมูล | เว็บใช้ไม่ได้ |
| `APP_NAME` | แถบหัว · หน้าล็อกอิน · ชื่อแท็บเบราว์เซอร์ | `บ้านเรา · Home Ledger` |
| `ACCOUNTS` | ปุ่มล็อกอิน · ตัวกรอง · ปุ่มเลือกบัญชีในฟอร์ม | ชุด 3 บัญชีเริ่มต้น |
| `BUDGETS` | การ์ดงบประมาณหน้าภาพรวมรายเดือน | อาหาร / เดินทาง / บันเทิง / เป้าหมายออม |
| `YEAR_GOAL` | การ์ด "คงเหลือสะสม" หน้าสรุปรายปี | 300,000 บาท |

**`BUDGETS`** เขียนเป็น `{ cat: "ชื่อหมวด", limit: จำนวนบาท }` จะกี่บรรทัดก็ได้
`cat` ต้องสะกดตรงกับหมวดหมู่ที่ใช้บันทึกจริง ไม่งั้นจะนับได้ 0
ชื่อหมวดแปลเป็นภาษาลาวให้เองผ่านรายการหมวดหมู่ ไม่ต้องไปเพิ่มคำแปลในไฟล์ `.dc.html`

`"เป้าหมายออม"` เป็นชื่อพิเศษ — หมายถึงเงินที่เหลือเก็บ (รายรับ − รายจ่าย) ไม่ใช่หมวดรายจ่าย
และตีความกลับด้าน คือ **ใช้ไม่ถึงเป้า** ถือว่าไม่ผ่าน

**`ACCOUNTS`** เพิ่ม/ลดกี่คนก็ได้ แต่ต้องแก้ให้ตรงกัน 3 ที่เสมอ:
`config.js` → บล็อกที่ 5 ของ `schema.sql` → สร้าง user จริงใน Supabase Authentication

ถ้าใช้บัญชีเดียว **ต้องตั้ง `'admin'`** ใน `schema.sql` ไม่งั้นจะแก้หรือยกเลิกรายการไม่ได้เลย

ที่ยังตรึงในไฟล์ `.dc.html`: ข้อความหน้าล็อกอิน (`t_hero1` / `t_hero2`) เพราะมีสองภาษา,
คำแปลลาวของ role ที่รู้จักแค่ `pin`/`ton`/`home` (id อื่นได้ข้อความไทยแทน ไม่ error),
และ `<title>` ใน `index.html` ซึ่งเป็นหน้า redirect ชั่วขณะ

## มือถือ

ใช้บนมือถือได้เต็มรูปแบบ ไม่ต้องซูม ไม่มีการเลื่อนซ้าย-ขวาทั้งหน้า
ทดสอบผ่านที่ความกว้าง 320 / 360 / 390 / 768 px ครบทุกหน้าจอ

จุดที่ปรับตามขนาดจอ (อยู่ในบล็อก `@media` ท้าย `<style>` ของไฟล์ `.dc.html`):

| ที่ | บนมือถือ |
| --- | --- |
| หน้า login | ซ้อนบน-ล่าง แทนการแบ่งซ้าย-ขวา |
| แถบหัว | ซ่อนโลโก้ · แท็บเลื่อนแนวนอนได้ |
| การ์ด KPI | 4 ช่อง → 2 ช่อง → 1 ช่อง (ตามความกว้าง) |
| ตารางรายการ | เลื่อนแนวนอนในกรอบตัวเอง ไม่ดันทั้งหน้า |
| กราฟ 12 เดือน | บีบช่องไฟและชื่อเดือน |
| ฟอร์มบันทึก | เรียงคอลัมน์เดียว |

สไตล์ในไฟล์เป็น inline ทั้งหมด กฎใน `@media` จึงต้องใช้ `!important` เพื่อทับ
และใช้คลาส `hl-*` เป็นตัวจับ — ถ้าแก้เลย์เอาต์เพิ่ม อย่าลบคลาสพวกนี้ทิ้ง

## ประเภทรายการ

| ประเภท | ทำอะไร | นับในรายรับ/รายจ่าย | นับในยอดคงเหลือ |
| --- | --- | --- | --- |
| รายรับ | เงินเข้าช่องทาง | ✓ | ✓ |
| รายจ่าย | เงินออกจากช่องทาง | ✓ | ✓ |
| **โอนระหว่างช่องทาง** | ย้ายจาก `method` → `method_to` | ✗ | ✓ (ย้ายที่เฉย ๆ) |
| **ยอดยกมา** | เงินตั้งต้นก่อนเริ่มใช้สมุด | ✗ | ✓ |

โอนใช้กับ **ถอน ATM** (โอน → เงินสด) และ **จ่ายบัตร** (โอน → บัตร)
ถ้าไม่มีประเภทนี้ ยอดแยกช่องทางจะเพี้ยนทันทีที่ถอนเงิน

## ยอดคงเหลือแยกช่องทาง

การ์ด 3 ใบบนหน้าภาพรวมรายเดือน — **สะสมตั้งแต่รายการแรกถึงวันนี้** ไม่รีเซ็ตรายเดือน

| การ์ด | สูตร |
| --- | --- |
| เงินสดคงเหลือ | ยอดยกมา + รับ − จ่าย + โอนเข้า − โอนออก ของ `เงินสด` |
| เงินในบัญชี | เหมือนกัน แต่ของ `โอน` |
| **ยอดค้างบัตร** | รายจ่ายบัตร − เงินที่โอนไปจ่ายบัตร → **เป็นหนี้ ไม่ใช่เงินคงเหลือ** |

**ถ้ายังไม่ได้ใส่ยอดยกมา** การ์ดจะขึ้นคำเตือนไว้ ว่าตัวเลขนี้เป็นยอดตั้งแต่วันแรกที่บันทึก
ไม่ใช่เงินจริงในกระเป๋า — ใส่ยอดยกมาครั้งเดียวต่อช่องทาง แล้วตัวเลขจะตรงกับความจริง

## ยกเลิกรายการ แทนการลบทิ้ง

ลบถาวรถูกปิดไปแล้ว (ไม่มี policy `delete`) เพราะ `txn_edits` ผูกด้วย `on delete cascade`
ลบรายการทีเดียว **ประวัติการแก้ไขทั้งหมดของรายการนั้นหายตามไปด้วย** ซึ่งขัดกับที่ตั้งใจไว้

แทนที่ด้วยการยกเลิก: แถวยังอยู่ ไม่นับในยอดรวมไหนเลย ในหน้ารายการจะขีดฆ่าและจางลง
พร้อมป้าย "ยกเลิกโดย ปิ่น · 3 ก.ย. 2569 14:22" กดปุ่ม **กู้คืน** กลับมาได้

`void_at` / `void_by` หน้าเว็บกำหนดเองไม่ได้ — trigger `txns_guard_void` เขียนทับด้วย `now()`
กับ `my_name()` เสมอ และปฏิเสธถ้าคนกดไม่ใช่ `is_admin()`

## เรื่องสกุลเงิน

แต่ละรายการเก็บสกุลเงินของตัวเอง (THB / USD / KIP) และแสดงผลด้วยสกุลนั้น

**ยอดรวมทุกที่แยกตามสกุล** ผ่าน `sumByCode()` เช่น `฿12,400  ·  ₭2,300,000`
ทั้งหน้าภาพรวมรายเดือน, **สรุปรายปี** (การ์ด KPI + ตาราง 12 เดือน), รายการทั้งหมด และหน้ามือถือ

ที่ยัง**แปลงเป็นฐานบาท**คือเฉพาะตัวเลขที่ไม่ใช่ยอดเงิน หรือจำเป็นต้องเทียบข้ามสกุล:
ความสูงแท่งกราฟ, % อัตราการออม, เดือนที่จ่ายมากสุด, งบประมาณ, เป้าหมายรายปี
ใช้อัตราคงที่ใน `CURRENCIES` — แก้อัตราได้ในไฟล์ `Home Ledger.dc.html`
